## Font Risk

The game uses TextMeshPro. `extracted/font_report.tsv` shows no Cyrillic ranges in the shipped TMP font assets. Russian text may render as boxes or blanks until a Cyrillic-capable TMP fallback is configured.

Planned runtime font fix:

1. Build or obtain a verified Cyrillic TextMeshPro font AssetBundle compatible with the game's Unity version. The game reports Unity `6000.2.7f2`.
2. Put the verified AssetBundle in the installed game root later, during the install/test stage.
3. Configure:

   ```ini
   [Behaviour]
   FallbackFontTextMeshPro=<asset-bundle-filename>
   ```

Do not download or distribute unverified font binaries. Record any later font asset version, URL/source, and SHA256 in `patches/xunity_autotranslator/DOWNLOADS.md`.

## resources.assets Investigation Pass

Detailed output:

- Script: `scripts/scan_resources_assets.py`
- TSV export: `extracted/resources_dialogue_strings.tsv`
- Findings report: `docs/resources_assets_findings.md`

Results:

- `resources.assets` does contain missing player-facing text. UnityPy reads two normal TextAssets:
  - `journals`, a semicolon-delimited table with `id`, `text`, `title`, and `chars`.
  - `dialogues`, a semicolon-delimited table with `ID`, `MAN`, `WOMAN`, and `WHO`.
- Earlier "empty TextAsset" findings were misleading for `journals` and `dialogues`; their `m_Script` payloads are populated and readable.
- `resources.resource` did not load as a Unity serialized asset and produced only an isolated raw `Row` hit in the known-string pass. No structured dialogue, journal, HUD, TMP, or TextAsset text payload was identified there.
- The Unity-aware scan exported 872 findings. From `resources.assets`, it exported 812 `journals`/`dialogues` TextAsset rows, 643 unique strings, with 635 unique TextAsset strings still outside the current queue after the targeted update.
- `level3` contains `End Day`, `Close Journal`, `I feel healthy!`, and the opening journal text as length-prefixed MonoBehaviour strings. UnityPy cannot decode these MonoBehaviour typetrees in this build, but raw offsets fall inside MonoBehaviour object ranges; `End Day` resolves to an owning GameObject named `Text (TMP)`.
- `End Day` is therefore not a texture/sprite based on this scan. It is serialized TMP/MonoBehaviour text or unhooked runtime TMP text if it remains English in-game.
- `I'm tired a bit` was not found in `resources.assets`, `resources.resource`, or `level1` through `level5`. Because the exact dictionary entry already exists, this status message is likely generated from code or assigned through a setter XUnity is not catching.

Dictionary update from this pass:

- Added exact TextAsset dialogue variants:
  - `… Why did you choose me?`
  - `.. I’m not sold on the idea that all this was a coincidence.`
- Added exact `A New Day` journal TextAsset variants for Frederik, Laurel, and Row.
- Rebuilt the generated dictionary and copied it into `game_runtime_test/BepInEx/Translation/ru/Text/_AutoGeneratedTranslations.txt`.
- Validation now passes with 590 active translations, 10 `needs_review`, and 31 `skip`.

Current interpretation:

- Some remaining English text was caused by dictionary mismatch: the observed dialogue screenshots used straight punctuation variants, while the serialized TextAsset source uses ellipses and curly apostrophes.
- If the newly added exact TextAsset dialogue strings still remain English after a full restart, treat dialogue bubbles as a hook limitation rather than continuing to add variants blindly. The existing `TMP_Text_SetCharArray_Hook3` warning remains relevant, especially if the game uses Febucci TextAnimator or a custom typewriter path.
- Journal text is partly covered by existing manual entries and the newly added exact opening variants, but the full `journals` TextAsset backlog is much larger and should be translated in a separate planned pass.
- HUD/status messages remain mixed: static exact keys such as `End Day`, `Close Journal`, `Condition:`, `Food:`, and dynamic value variants are in the dictionary, but code-generated status lines may need hook/config testing.
- BruteForceFix was not installed or tested in this pass. Recommended next step is a full game restart from `game_runtime_test`, then manually test dialogue bubbles, journal opening text, HUD/status messages, and `End Day`. Only if exact dictionary keys still do not translate should the next pass investigate official `AutoTranslator.IL2CPP.BruteForceFix`, record URL/version/SHA256 in `patches/xunity_autotranslator/DOWNLOADS.md`, and install it only in `game_runtime_test`.
