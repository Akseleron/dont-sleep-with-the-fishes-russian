# Fishing Weight Issue Notes

## Current Symptom

- Fishing result weight remains English in runtime screenshots, for example:
  - `Weight: 0.28kg`
  - `Weight: 1.21kg`
  - `Weight: 2.77kg`
  - `Weight: 25.97kg`
- Fish names and some `(+N Food!)` text translate, but the dynamic weight line does not reliably translate.

## What Was Tried

- Earlier generated exact dictionary ranges were added for many values:
  - `Weight: 0.01kg` through `Weight: 20.00kg`
  - `Weight: 0.1kg` through `Weight: 20.0kg`
  - rich text variants such as `<b>Weight:</b> 0.66kg`
- Those rows were removed from `translations/source_queue.tsv` after manual QA because:
  - exact ranges do not cover all possible runtime values, such as `Weight: 25.97kg`;
  - screenshots showed weight still English even when some exact-style entries existed;
  - thousands of generated exact rows made the dictionary noisy without fixing the root problem.
- Current expected state: `weight_rows_left = 0` in `translations/source_queue.tsv`.

## Current Minimal XUnity Regex Experiment

- Added `patches/xunity_autotranslator/BepInEx/Translation/ru/Text/FishingRegex.txt`.
- This file is intentionally outside `_AutoGeneratedTranslations.txt` because XUnity ignores regexes in generated `_` files.
- Current rules:
  - `Weight: Xkg` -> `Вес: X кг`
  - `<b>Weight:</b> Xkg` -> `<b>Вес:</b> X кг`
  - splitter regex for `<FishName> (+N Food!)`, so fish names and food suffixes can be translated separately if XUnity sees the full composite string.

## Likely Causes If Regex Still Fails

- The game may update the weight through an unhooked TextMeshPro setter.
- The text may be assembled through `TMP_Text.SetCharArray`, consistent with the existing XUnity warning:
  - `Could not hook 'TMP_Text_SetCharArray_Hook3'`
- The visible text may be split between multiple TMP components or assigned after XUnity's text path logging/translation pass.
- Hidden rich text or formatting may differ from the visible string.
